## 标签是怎样得到的

本轮由Codex对879张raw进行单次AI视觉研究标注，逐批查看30页等比例联系表。对18个暗部/边界样本、4组相似候选另作大图预览比较，并补看4张重度低照度原始整图。没有人类专家双人复核或标注一致性测量，不能称为UIEB官方标签、物理真值或经过外部验证的严重度等级。

判据见[划分方案](UIEB_RECLASSIFICATION_PLAN.md)：每项0～3级，取最大已识别退化等级决定light/moderate/severe。主类别是一项最大等级退化，其他已识别退化记录在CSV。未列出的类型记0只表示本轮未见明确证据，不能证明该退化不存在。

只查看raw进行分类。reference仅用于配对、尺寸与重复冲突核验，不用于标签、程度和样本筛选；未运行源模型、未使用PSNR分档；未读取旧分类/评分决定标签。RGB/亮度统计只作描述性核查，不是自动打标签公式。

当低对比度可能同时来自失焦或其他因素时，保守放入中度。例如573_img_.png从初轮重度候选调整为中度；450、476、907的主类在大图复核后改为雾化。所有最终等级与索引保存在UIEB_V2_LABELS.csv及UIEB_V2_VISUAL_ANNOTATIONS.json。

## 近重复与场景边界

识别并视觉确认3组非精确重复内容：356/61、705/828、727/832。分别记录near_001、near_002、near_003，均没有跨轻度和重度。453/874虽pHash相近，但构图与主体不同，没有合并。

这是精确重复加有限pHash候选的核查，不是完整场景级隔离认证。UIEB缺少可靠的完整场景ID，仍可能存在未被检测到的同场景不同视角。后续轻度源训练/验证划分至少应让上述已知组整体分配，不能把同组两个版本拆入训练与验证。

## 域差异的证据与限制

同类的描述性统计显示：偏蓝类的逐图B/(R+0.02)均值从轻度约1.78增加到重度约12.21；偏绿类G/(R+0.02)从约1.38增加到约3.94；雾化类亮度空间标准差从约0.152降到约0.088。这些是缩小预览后的辅助raw统计，并不证明真实物理参数，也没有排除场景内容影响。

低照度组的整体亮度/暗像素比例没有形成所有指标严格单调的三档。原因包括主体局部欠照与背景照明不同、混合偏色，以及每档数量很小。因此不能宣称四类在所有客观指标上已经完全分离。该类需保留单图检查和小样本说明。

本轮建立了可审阅的视觉轻重划分，但没有测量新Source-only指标，不能承诺源模型PSNR必然降低或TTA一定改善。两端场景与类型比例也不同，不能将后续结果差异全部解释为纯严重度效应。后续应同时报告逐类结果、按样本总体均值和逐类均值，防止偏蓝83张掩盖低照度4张。

## 查看与复核

在文件管理器双击数据根目录review.html，可筛选程度及主类别。点击缩略图打开原始复制文件；CSV还记录次要退化及0～3级。

本次构建命令（在开发机项目根目录执行）：

```powershell
cd E:\Codex\DCTTA-main\movetoUIE
python reclassify_uieb.py --source E:\dataset\UIEB --labels docs\10_20261015_dataset_reclassification\UIEB_V2_LABELS.csv --eligibility docs\10_20261015_dataset_reclassification\UIEB_V2_ELIGIBILITY.json --output dataset\UIEB_reclassified_v2
```

增加`--verify-only`可再次核对已有复制结果和原始数据，数据源必须仍为本机E:\dataset\UIEB。正常重跑跳过内容相同的图片；图片或元数据不同则拒绝覆盖。不要混用修改后的标签直接覆盖本版目录。

若带到程序机，直接同步整个`dataset\UIEB_reclassified_v2`到`F:\qmh\DCTTA-uie\dataset\UIEB_reclassified_v2`，不打包、不移动原始文件。配套同步本阶段docs和两个数据脚本、专项测试。未来源/目标数据入口应读本版相对路径清单。

**当前train_source_uie.py/adapt_target_uie.py仍是旧蓝色weak/strong协议，尚未适配新目录。不要直接套用旧蓝色运行命令开始训练。** 下一步是单独冻结轻度训练/验证清单和混合目标顺序，再建立新Source-only；G0–G7仍对应旧源权重与旧目标集。

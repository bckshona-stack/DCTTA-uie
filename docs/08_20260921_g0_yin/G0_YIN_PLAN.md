# G0 学生原图输出补诊断方案

日期：2026-09-21。状态：方案A；代码已实现，本地小图测试通过，正式数据待程序机运行。

## 目标与范围

复用 G0 strict v2 的 `run/snapshots/000000.pth` 至 `000133.pth`，观察固定10张典型图的学生原图输出 y_in 与教师随更新的变化。不是新增适应实验，不分配新的 G 组编号，不重新训练、不运行 RDDM、不修改原权重。

选图严格复用 visual_v2 的 selected_samples.csv 和 run_manifest.json。整图、原分辨率、float32、batch=1、原 NU2Net pad8 接口，不缩放、不切图、不混合精度。

## 输出约定

- 11阶段：0、14、27、40、54、67、80、94、107、120、133。每阶段保存10张 y_in，共110张PNG，放入 student_raw/<六位步数>/。
- 134时刻：每个时刻对10张图计算 student_raw_psnr（y_in）、teacher_pseudo_psnr（原八视图教师伪标签）、teacher_raw_psnr（教师单视图）。共1340行逐图指标。
- 教师单视图取八视图中已有的恒等视图，不额外执行模型前向。与 student_raw 对比，减少八视图平均带来的混杂。
- 另记 source_only PSNR、学生相对 source_only 的差值、学生与单视图教师的差值；保存图片的阶段同时记录 PNG 量化后 PSNR。
- summary.csv 为10张典型图的各时刻平均值，不能视为全部133张目标域的均值。

PSNR按原诊断口径：RGB float32 截断到[0,1]后平方，float64平均，data_range=1。PNG先四舍五入量化为uint8；量化后PSNR单独记，不混用。

## 对齐与验收

第0步为初始化状态；第k步为完成第k张适应图片后的学生和教师状态。教师是参数EMA，不是直接把学生输出图像拷贝为标签。当前保存的是每次适应后的状态，不包含一次适应内部的每个优化子步骤。

预检检查原始严格诊断与visual_v2完成状态、数据清单、源权重身份、实现版本、数值配置、选图、全部134个小权重的存在与SHA256。允许GPU可见数量与原运行不同，PyTorch/CUDA等相关版本、数值配置和原模型实现必须一致。

每个阶段教师八视图PSNR与旧visual_v2指标核对；已有逐步学生评估覆盖的图片也核对，绝对容差1e-5 dB。差异超限停止，不自动放宽。完成要求110张图片和1340行指标齐全。

每时刻原子提交进度；中断重启最多重做一个未提交时刻。已提交图片校验SHA256，输入权重变化或运行约定改变时拒绝续跑。输出使用独立目录，不覆盖旧visual_v2；同一输出目录只能运行一个进程。

## 资源与解释边界

当前选图的PNG保守估计加元数据预留约0.316 GB；10 GB参数是新增目录的磁盘容量上限，不是RAM或显存上限。已有历史权重不复制。只实例化一个NU2Net，依次加载学生/教师，逐图推理，无RDDM及优化器。正式显存峰值待程序机验证，不承诺小于10 GB。

总计134×10×9=12060次整图前向（学生1次、教师8次），最大图2180×1447，因此耗时不能按110张保存图片估计。

曲线可定位学生、教师从哪个观测步开始恶化，不能单凭先后顺序证明因果。还要结合G1/G5固定教师等对照，区分学生监督、生成器条件、EMA反馈的作用。旧图红线仍是y_sd；新结果不能把它直接改名为y_in。
